# OpenAPI Implementation Map

Snapshot source: current `openapi.json` in this repository.

This document tracks frontend coverage for the backend route surface. It is a working implementation map, not a completion claim.

## Schema source and synchronization contract

The source of truth for the HTTP route schema is the running FastAPI application's
`/openapi.json`. The Web repository keeps two derived files:

- `openapi.json`: fetched by `npm run api:pull` from `DATUS_OPENAPI_URL`,
  `VITE_DATUS_API_TARGET`, `DATUS_API_TARGET`, or the default `http://localhost:8000`;
- `src/types/openapi.ts`: generated by `npm run api:types` with `openapi-typescript`.

Use the combined command when the backend route or response model changes:

```bash
npm run api:sync
```

Do not hand-edit either generated file. A route change is incomplete until the backend response
model, generated schema, generated TypeScript types, API helper, composable/UI consumer, and focused
tests have been checked together. `openapi-implementation-map.md` describes frontend coverage; it
does not replace the generated schema or route security matrix.

### Tracked-schema verification snapshot

The current tracked snapshot contains OpenAPI `3.1.0`, with **164 paths and 201 operations**.
The generated `src/types/openapi.ts` contains the same 164 path keys. This is a static comparison
of tracked files; it does not prove that a running backend at the configured API target emits the
same schema. Use a temporary directory or disposable checkout when regenerating for comparison.

The enterprise route-security source currently contains 201 unique method/path keys, and its
static path comparison with the tracked schema is empty after normalizing FastAPI path converters.
The runtime equality check remains `datus-agent/tests/unit_tests/api/enterprise/test_route_security_matrix.py`;
an import failure or environment-specific router projection can only be detected by running that test.

`StreamChatInput` has one known generated-type caveat: the backend/OpenAPI contract requires only
`message`; `plan_mode`, `max_turns`, and `prompt_language` have backend defaults. The current
generated TypeScript marks those three fields as non-optional, while the web request builder omits
them and relies on backend defaults. Do not hand-edit the generated type to resolve this; verify
the backend schema and generator version in a temporary output first.

## Error-layer contract

The frontend must keep these failure layers distinct:

1. HTTP status errors (`401`, `403`, `404`, `503`) are raised by `src/lib/request.ts` as
   `HttpError` and may trigger the authentication failure handler;
2. `Result(success=false, errorCode, errorMessage)` is parsed by `extractResultData()` as
   `ApiResultError`;
3. Chat pre-check and runtime failures can arrive as an SSE `error` event while the HTTP response
   remains a successful `text/event-stream` response.

Do not make a UI success state depend only on HTTP `200`, and do not convert every SSE/application
error into a generic transport error. Session/history refresh and cursor handling must remain tied
to the canonical Chat event and history contracts.

## Current CI status

The Web quality workflow currently runs lint, maintenance-rule tests, a read-only
`npm run api:check`, Vitest, browser tests, typography checks and build. `api:check` regenerates
TypeScript from the committed `openapi.json` in a temporary directory and compares it with the
committed `src/types/openapi.ts`; validation does not overwrite the working tree.

This static check does not contact a backend and therefore cannot prove that the committed
`openapi.json` matches the OpenAPI document emitted by the intended FastAPI deployment. Whenever a
route or response model changes, run `npm run api:sync` locally against that backend and review the
generated diff. Live schema verification remains an environment-specific smoke check.

## Frontend request boundary

Runtime backend API calls in `src/` must go through `src/lib/request.ts` and the API helpers. The
only additional runtime `fetch()` currently identified in `src/` reads a browser-local `blob:` URL
and converts it to a data URL; it is not a backend request or an authentication bypass.

`src/lib/request.ts` may attach both the legacy `X-Datus-User-Id` compatibility header and a
Bearer token. Enterprise authorization must continue to use the server-side Bearer/signed-identity
boundary; a bare frontend user-id header is not an enterprise authorization decision.

The OpenAPI sync script, API smoke script, and browser-test launcher use direct `fetch()` by design
because they are standalone verification scripts. They do not establish a frontend component API
boundary.

The request helper, current user/token resolver, chat runtime cache and session-history cache are
browser-tab/module state. Workspace unmount disposes chat controllers and history state, but an
account switch in the same tab still requires an auth/logout E2E check before it can be treated as
complete isolation.
